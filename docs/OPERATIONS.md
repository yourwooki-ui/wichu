# Operations

## 운영 목표

1차 출시는 소규모 단계 배포를 전제로 한다. 운영자는 가입 실패, 후보 고갈, Pick 저장 실패, Match 누락, 메시지 실패, 신고 적체를 버전과 환경별로 확인할 수 있어야 한다.

## 핵심 지표

- 앱 시작 성공률과 crash-free session
- 가입 시작 → 18+ 검증 → 프로필 완료 전환
- 후보 batch 성공률/지연, local queue 잔량, 이미지 prefetch 실패율
- Pick 저장 성공률과 Match 생성 지연
- 메시지 전송 성공률/지연, Realtime 재연결
- 신고 접수량, 최초 검토 시간, 차단/탈퇴 완료율

초기 목표값은 preview 계측 후 확정하며, 숫자가 없는 상태를 정상으로 간주하지 않는다.

## Incident 등급

- **SEV-1**: 광범위한 로그인/채팅 불가, 데이터 노출 또는 결제 오작동 — 즉시 신규 배포 중지, 영향 차단, 담당자 호출
- **SEV-2**: 일부 핵심 기능 장애, 신고/차단 실패, 반복 crash — 당일 완화 및 원인 추적
- **SEV-3**: 비핵심 UI/번역/분석 오류 — 다음 안정화 배포에 포함

모든 incident는 시간선, 영향 사용자, 완화, 근본 원인, 재발 방지 항목을 남긴다. 민감 데이터는 incident 문서에 복사하지 않는다.

## 안전 운영

- 신고는 위험도와 최근 반복 신고를 기준으로 triage
- 즉각적 위험·불법 콘텐츠는 해당 정책과 관할 절차에 따라 escalation
- 차단은 클라이언트 UI가 아니라 RLS/서버 권한에 즉시 반영
- 운영자 접근은 개인 계정, 최소 권한, 감사 가능한 방식으로 수행

## 정기 점검

- 매일: crash/API/신고 queue/결제 이상 확인
- 매주: 후보 품질, Match·Chat funnel, 차단률, 앱 버전 분포 확인
- 릴리스 전: backup/rollback, migration, feature flag 또는 배포 비율 점검
- 분기/정책 변경 시: 보존·삭제·스토어 고지와 실제 동작 일치 확인
